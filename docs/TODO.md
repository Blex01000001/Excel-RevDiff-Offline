## 已知問題／限制

- 有密碼保護的檔案讀不了。
- 很舊的 Excel 5.0/95 版 `.xls` 與 Big5 編碼的 CSV，中文可能亂碼（內嵌的是 SheetJS core，沒有 codepage 表）；建議先另存 `.xlsx`。
- 同 Key 的列太多時（剩餘 A×B 超過 `GREEDY_LIMIT` = 40000）改依出現順序配對，結果可能不準；畫面有紅色警告。這是刻意取捨（否則會卡死）。
- 資料會同時存在 Worker（整本活頁簿）與主執行緒（列資料）；記憶體用量改成 Worker 後沒有重新量測，數十萬列以上仍可能讓分頁當掉。主執行緒仍要建立列物件與重建結果，最長約停頓 0.3 秒。
- SheetJS 讀檔會解析整本活頁簿的所有工作表，不只選到的那一張。
- 匯出時「修改」的儲存格是文字 `舊 → 新`（不是數字）；數量差值欄才是數字。
- 空白標題的欄位名稱固定為 `Col{n}`（不翻譯，因為欄名同時是資料鍵）。
- 標題列自動偵測只看前 30 列；日期以 `yyyy-mm-dd` 字串比對。
- 匯出檔名刻意用英文（`compare_result_日期_時間.xlsx`），因為 headless Chromium 下中文檔名會失效。
- 舊瀏覽器（例如 IE）不支援 SVG 頁籤圖示與部分語法。

## 想法

- 正規化規則可開關（大小寫、全形半形、數字容差）。
- 兩檔欄位名稱不同時，提供欄位對應。
- 以虛擬捲動取代「再載入 500 列」。
- 依欄位名稱記住上次的 Key／比對／數量設定（localStorage）。
- 「互換 A/B」按鈕。
- 新增／刪除列的數量也計入差值合計（可選）。
- CSV 編碼選擇（UTF-8／Big5）。
- 一次比對多個工作表。
- 複製或列印結果。
- 改善「建議 Key」：目前以欄位名稱與資料區分度猜測，只是起點。
- 把 `parseSlot()` 的建列與結果重建也搬進 Worker，並用更精簡的格式傳遞（目前主執行緒最長凍結約 0.3 秒）。
